# S5 plan correction: 2026-11-17, S5b-2

Part of [the S5 plan](../S5.md), section 12, "Corrections".

- **2026-11-17, S5b-2.** Archive, restore and copy, server and field-rules slice (`web/src/lib/jobs/archive.ts`, `archive-store.ts`, the routes under `docs/access/jobs.md` "Archive, restore and copy"; owner decision 2026-11-16: the screens, Archive, Archived drafts with Restore and Copy, follow in S5b-2b), with no new capability key and no migration, and these choices the plan left open. (a) Archive and restore carry the job `revision` and a `changeId`, as the customer save; the same change again is the same answer. "Unsigned draft" is a job in `draft` or `submitted`; a signed one is refused (409 `job_signed`). (b) Archive waits while a Submit of the job is unsettled (a pending row, or a decided row whose field marker is not written yet): 409 `submission_in_progress`, so no fence, release or marker ever meets an archived draft. (c) The field draft's `archived` state is set after the Postgres commit, in a Firestore transaction with `archiveRevision` (the job revision), so a slower archive never lands after a newer restore; restore changes the state only of a draft that is archived. The field rules' logic is unchanged: a client already writes only while `state` is `editing`, so `archived` refuses every client write; the rules file's comment names the new state and key. (d) Restore finds the status from the job's submissions (S5a-2 (f)): `submitted` when the current draft has a committed one, else `draft`. Archive and restore each move the job revision, so a signing link of a submitted job is voided and stays voided after restore, and its estimate is made again. (e) "New client ids" are the new job's and first draft's ids, made on the phone; the copy keeps the signed record's room ids, which are scoped by the draft. (f) "Transcripts and approvals cleared": the field map holds no transcript (a Live walkthrough's is never kept in a draft) and one approval, `scopeConfirmed`, which the copy leaves out, as the old app did. The copy takes the signed record's property address, field map and rooms from its snapshot, and not the customer, the claim or the photo references (the photos are the signed job's evidence). (g) The owner's "Archived drafts" list is `GET /api/jobs?scope=archived` (`jobs_archive`). (h) As on every job route, a role check comes before the job is looked at, so a role that lacks a route's key is answered 403, not 410, for an archived job.
