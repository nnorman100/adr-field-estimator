# S5 plan correction: 2026-11-13, S5a-6

Part of [the S5 plan](../S5.md), section 12, "Corrections".

- **2026-11-13, S5a-6.** The job screens (`web/src/app/field/`, `web/src/lib/field/`) use no new route, capability key or migration, with these choices the plan left open and two decisions taken while building. (a) Every screen (Jobs, New job, Check Scope, Customer and claim, Photos) is a view of `/field` chosen by the address's query (`/field?job={id}&view=photos`), because the field worker answers every `/field` address with the one kept shell page; `web/tests/e2e/screens.ts` lists each view (`FIELD_VIEW_SCREENS`) with the spec that runs axe on it, and a unit test fails on a view with no entry. (b) Removing a room (owner decision 2026-11-13): `web/firestore.rules` lets the draft's field owner delete a room document while the draft is `editing`, and the phone removes it from `roomOrder` in the same batch; a photo reference is never deletable, and a photo tagged to a removed room shows untagged. The S5a-1 emulator assertion that refused the field owner's room delete now expects it allowed, beside new refusals for every other caller and for a draft no longer editing. (c) The browser tests run a second app server on a throwaway PostgreSQL 16 (set up as `npm run test:db` does) with the Storage emulator in place of the evidence bucket (firstmate decision); the `e2e` job in `.github/workflows/web.yml` gained the `database` job's PostgreSQL install step and nothing else. The Storage emulator does not enforce `ifGenerationMatch=0`, so the real create-only precondition stays S5a-12's check. (d) A photo is redrawn on the phone at most 2,560 px on its longer side as a JPEG before it is sent, which also leaves the camera's location metadata behind; the full-size original stays S6-5. (e) Office reads the field work and photos only, and may save the customer and claim (J3); the forms are plain controls in the shadcn/ui style checked by the S5a-1 Zod schema (no form library added). (f) The phone shows no pre-1978 wording; it comes with the estimate from the server (S5a-9).
