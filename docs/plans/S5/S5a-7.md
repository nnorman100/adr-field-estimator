# S5 plan, step S5a-7

Part of [the S5 plan](../S5.md), section 5, "Ordered steps".

**S5a-7 Submission, estimate, pin and agreement tables (DB job).** DB: `job_submissions` (client id, draft, epoch, status pending/committed/aborted, expiry, snapshot bytes and SHA-256, request digest, marker state, kind original/change-order, parent agreement; unique per draft and epoch, one committed row per draft, and a trigger that refuses changes to a committed or aborted row), `job_price_pins` (pricing plan S5a-1, unchanged), `job_estimates` (submission, pin, table hash, engine version, priced result, proposal bytes and SHA-256; unique per submission and pin), `agreements` (client id, job, submission, estimate, kind, parent agreement, signer kind device/link, signer name, signature evidence id, proposal SHA-256, priced result with version id, content hash and engine version, documents bytes; insert-only; one original per job), and a cross-company "due markers" function for the worker, on the S3-12 pattern. Runtime: `SELECT, INSERT` everywhere, plus `UPDATE` on the submission's status, snapshot and marker columns only. Tests: guard test; agreements, estimates and pins insert-only; a committed or aborted submission cannot change; one original agreement per job; a pin cannot name another company's version. Needs: S4-5, S5a-2, the lane.
