# S5 plan, step S5a-R

Part of [the S5 plan](../S5.md), section 5, "Ordered steps".

**S5a-R Field-rules release to test (J10 option B).** BE, DB: none. Adds a job to the release workflow (`.github/workflows/web-release.yml`) that deploys `web/firestore.rules` to the `test` field database `dryscope-field-test` after the app is released, then reads the deployed ruleset back and fails the release if it differs from the committed file. Needs an IAM change (a rules-deploy role on the deploy account, `test` project only, never live) and a workflow change: High risk, owner approves once; the agent never sets IAM or edits workflows without that approval, and the Test guard rules for workflows apply. Live is untouched; a live rules release stays a separate owner step. Tests: the workflow job runs only on `master` for `test`; a rules file that fails the emulator tests never reaches the job; a failed deploy fails the release and leaves the last good ruleset. Needs: S5a-1 (something to release); the owner's one approval. Must land before the hands-on check. **As built:** a step in the release's deploy job before the new revision is staged, not after the app is released, so a rules error or a refused call stops the release with nothing to undo; it reads the release and ruleset back and fails unless they hold the committed file. The role (`dryscopeRulesReleaseTest`) cannot be limited to `test` in IAM: Firebase Rules takes no IAM condition and test and live share project `dryscope`, so "never live" is held by the script and workflow, not by IAM (`infra/dryscope/README.md`, "Accepted risks").
