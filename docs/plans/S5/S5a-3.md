# S5 plan, step S5a-3

Part of [the S5 plan](../S5.md), section 5, "Ordered steps".

**S5a-3 Jobs API.** BE: `POST /api/jobs` (job id and first draft id from the phone; Postgres row first, then the Firestore draft with `fieldOwnerUid` and `editing`; a retry creates whichever part is missing), `GET /api/jobs` (company jobs or my jobs, paged), `GET /api/jobs/{id}`, `PUT /api/jobs/{id}/customer` and `/claim` (revision plus change id). The job-access function. Who writes customer and address follows J3. DB no. Tests: same create twice gives one job and one draft; same id, different body 409; a lost response on a customer save then a retry gives no false conflict; an estimator never lists another estimator's job; a B owner gets 404 on each A route. Needs: S5a-2; S3-12 (the server Firestore client).
