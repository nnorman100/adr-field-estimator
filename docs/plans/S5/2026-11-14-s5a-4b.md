# S5 plan correction: 2026-11-14, S5a-4b

Part of [the S5 plan](../S5.md), section 12, "Corrections".

- **2026-11-14, S5a-4b.** Migration `0013_company_documents` and the profile routes' letterhead lines and document settings (`web/src/lib/profile/settings.ts`, `web/src/lib/profile/`, Company settings; `docs/ACCESS.md` "Company profile API") use no new capability key, with these choices the plan left open. (a) The letterhead columns are one line each with 0010's rules (trimmed, no control characters): emergency phone and fax 80 characters, website 200, tagline 150, mailing address 500. `profile_documents` is `'{}'` until set, and SQL checks only that it is an object whose text form is under 65,536 bytes; the schema allows at most 64,000 bytes of JSON so a value it passes is never refused by that check. The trigger split is 0010's function replaced in place (`CREATE OR REPLACE`, now naming the six columns); the trigger itself is unchanged. (b) The schema: a clause is a title of 1 to 120 characters on one line and a text of 1 to 2,000; a prep task is 1 to 300 characters on one line; the clause text, the authorization and the payment terms keep line breaks and refuse every other control character and half of a surrogate pair; each text is stored and returned exactly as entered, leading spaces and line breaks included, its length limit counts it with the ends trimmed, and a title, clause text or prep task of only blank space is refused; every key has its neutral default, so `'{}'` reads as the defaults; an unknown key anywhere is refused. A stored value that does not read is never used: the read answers 503 `profile_unavailable`. (c) A save may leave out the letterhead lines and `documents`, and each one left out keeps what is stored, so a phone with an older Company settings screen (S6's cached shell) cannot clear them; `documents`, when sent, is the whole object, a setting left out of it being its default. The five S5a-4 lines stay required. The audit count counts each letterhead line and each setting. (d) `companySetupMissing` takes the two texts as a second argument and lists "Start-work authorization" and "Payment terms" after the other fields when they are empty; the profile answer passes them (the screen now says "Still needed before documents can be issued and signed"), and the documents pass none, so what makes a document signable is unchanged until S5a-11 refuses signing without them. (e) The screen sends a clause or prep task row left entirely blank as nothing, rather than having it refused. (f) Tests: the upgrade tests of 0011 and 0012 compared `SELECT *` of `companies` before and after every later file; they now compare the columns that existed up to 0012, as 0010 did for 0009's test, and 0013 has its own upgrade test; the column-grant lists in `evidence-profile.test.ts` and `platform-operator.test.ts` name the six new columns.
