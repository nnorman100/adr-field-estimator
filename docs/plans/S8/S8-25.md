# S8 plan, step S8-25

Part of [the S8 plan](../S8.md), section 5, "Ordered steps".

**S8-25 Urgent fix: a new image straight to Cloud Run (M, High: a new workflow, live).** Kind: agent code; the owner approves the workflow. It must be merged and approved before switch-over day (S8-24).
- CI: a manual-only workflow, `web-urgent-fix.yml`, as the Standard's Core release path asks: "a manual-only workflow deploys a new image straight to Cloud Run with no infrastructure changes; the same release then goes through the normal path." One input: a commit on `master`. It has no environment selector. It builds the image once, from that commit, and its digest is the release: the same digest goes to test, then (after test's checks pass on that digest, section 3) to live, and the normal release later promotes that exact digest and builds nothing.
  - Test, then live. On test it deploys the digest as a new revision of the existing web app service with no traffic, and runs the smoke check at the candidate address. Then it moves the traffic and checks the serving address (`test.<domain>`) for the new commit and version. On any failure it puts the recorded traffic back. The live leg is the existing S8-18 sequence, by reference and not rewritten: copy the digest into live's repository and check it is unchanged, wait for the environment approval, stage, run the read-only candidate check, record the serving revision's traffic, move the traffic, check `app.<domain>` for the new pair only, and put the recorded traffic back if the move or the check fails. Live never runs before test has passed on the same digest.
  - Shared lock and drain. The workflow takes the same per-environment release lock as the release and rollback workflows, so no other rollout runs between its candidate check and its traffic move, and before staging it waits on the drain precondition (section 3: every revision without traffic at zero instances, or 15 minutes after the last traffic move), so at most two revisions hold database connections.
  - Eligibility. It refuses a commit unless the target already holds everything the commit needs. The workflow lists the paths changed between the serving revision's recorded commit (S8-19's manifest) and the chosen commit, and refuses if any is a migration, a field rules file, a Terraform file, or a setting the app reads from its environment. Such a commit goes through the normal release only.
  - Record. It writes the same manifest as a normal release (S8-19: image digest, version, revision, the traffic replaced, the rollback command), marked urgent, so the one-tap rollback reads it.
  - It never runs Terraform, a migration or a rules release, and never changes a service setting other than the image.
- The normal release follows with the same digest and version. A manual run of the release workflow, given the urgent release's version as its input (as S8-18's live leg already takes one), selects that recorded digest and does not build, so it does not matter that `master` has moved on. It runs the migration and the rules the urgent run skipped and adds its own record to the same manifest without replacing the urgent entry, so the urgent rollback command stays. The next ordinary release is refused until that run has finished.
- Docs: the urgent-fix section of the owner's release runbook (S8-20): when to use it (a commit that passes the eligibility check), that it moves test first and live only after test passed, and how to run the normal release of the same version.
- Tests: the workflow guard tests: manual dispatch only; one input and no environment input; no step runs Terraform, a migration or a rules release; the image is deployed by digest, and the live digest equals the test digest; no live step runs before test's check passed; the live smoke check is the read-only one and runs with `--env live` only; the release lock and the drain check come before staging; the serving address is checked after the traffic move and the recorded traffic is put back on failure; a commit that changes a migration, a rules file, a Terraform file or an environment setting is refused; the normal release given the urgent version reuses the recorded digest and builds nothing, and leaves the urgent record in the manifest.
- Needs: S8-14 for test; S8-18 for live; S8-19's manifest reader for the rollback command.
