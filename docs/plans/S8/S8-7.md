# S8 plan, step S8-7

Part of [the S8 plan](../S8.md), section 5, "Ordered steps".

**S8-7 Load test kit (M, Medium).** Kind: agent code; run in S8-22.
- BE: none. A script, `web/scripts/load-test.ts` (plain Node, no new dependency), with its scenarios and `web/load/pass-marks.json`. It signs each load user in once and reuses the token, so the test measures the app and not Google's sign-in limits. Scenarios: the morning opening (everyone opens the app within a minute), a field day (job list, one job, the item list, a photo every 30 seconds in bursts of ten, customer and claim saved, Finish, estimate, documents), an office day (list refresh, open job, documents). Photos are 1 MB of fresh bytes each, so every upload is a new file. It never calls an AI route. At the end it lists what it made through the app and compares counts: every record exactly once. It prints percentiles and exits non-zero when a pass mark fails.
- Pass marks, written before any run: 95% of reads under 2 seconds (the Standard's target); a 1 MB photo under 5 seconds at the 95th percentile; Finish under 5 seconds; errors under 2% and none from running out of database connections; every created record present exactly once; Cloud Run below its instance limit; database processor under 80% and connections under the limit less 10.
- Guards: it accepts only the test address and refuses any host that is live; it works only in a company whose name starts with `load-`; the load users' password is read from a prompt or the environment, never from an argument or a file in git.
- Tests: CI runs it for ten seconds with two users against the browser suite's local server and checks the report; a deliberately slow stand-in route fails a pass mark; a live host is refused; the percentile arithmetic has unit tests.
- Needs: nothing. Can start now.
