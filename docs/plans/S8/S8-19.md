# S8 plan, step S8-19

Part of [the S8 plan](../S8.md), section 5, "Ordered steps".

**S8-19 Roll back with one tap (M, High: a new workflow).** Kind: agent code.
- CI: a manual workflow, `web-rollback.yml`, with two inputs (environment, version). It reads that release's manifest, refuses when the revision to return to no longer exists, waits on the drain precondition unless that revision is the one the last move replaced (section 3), moves the traffic back, runs the smoke check (read-only on live), and notes the rollback on the release. On live it waits for the same environment approval. It never touches the database or the rules.
- Tests: the workflow guard tests; the manifest reader's unit tests; an unknown version is refused; the workflow holds no step that runs a migration.
- Needs: S8-14 for test; S8-18 for live.
