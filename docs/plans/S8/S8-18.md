# S8 plan, step S8-18

Part of [the S8 plan](../S8.md), section 5, "Ordered steps".

**S8-18 The live leg of the release (L, High: workflow, live).** Kind: agent code; the owner approves the workflow once and creates the GitHub environment.
- CI: `web-release.yml` gains the jobs of section 4.3 after test's record job: copy the image by digest, wait in the environment `live` (L8: the owner approves each live rollout), run `dryscope-migrate-live`, release the field rules to live, stage the candidate, run the read-only check on `candidate.app.<domain>`, record the serving revision's commit and version, move ten percent, check again (the candidate's pair on `candidate.app.<domain>`; the candidate's or the recorded pair on `app.<domain>`), move all traffic, check `app.<domain>` for the candidate's pair only, put the traffic back on any failure, release the relay the same way (staged and checked at `voice-candidate.app.<domain>`, then traffic, then checked at `voice.app.<domain>`), and add the live part to the release's record. Its variables are held to the live pool and the live accounts, as the test ones are held to test. One live release at a time; only the newest released version can be waiting, so an old one is never approved by mistake. A failure writes the failed-release line for live.
- Tests: `tests/test_web_release_workflow.ts` and a sibling file: the live jobs need test's record job; no live job names a test account and no test job names a live one; the live check runs with `--env live` only; traffic moves only after the check; only the check during the ten percent passes the previous pair, and the check after all traffic does not; the relay's check calls its candidate address before its traffic moves; the rules script runs for live only inside the live job; permissions stay minimal.
- Owner: create the environment `live` (branch `master` only, the owner as required reviewer) and its variables. The step first confirms that the repository's GitHub plan offers required reviewers on a private repository; if it does not, the live jobs start only from a manual run the owner makes, which is the same approval by another route.
- Needs: S8-8 to S8-10 merged and live's data root applied (owner step G); S8-14; S8-17. Until live's app root is applied (owner step L), a run stops after the image copy and prints the digests, as test's first run did; the full leg runs from owner step Q.
- Later, not in this step: after three clean live releases and both drills, a small pull request (High, workflow) lets a release that carries no database change skip the approval. A release that changes the database always waits for the owner (L8).
