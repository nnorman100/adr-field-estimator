# S8 plan, step S8-3

Part of [the S8 plan](../S8.md), section 5, "Ordered steps".

**S8-3 Records check after a restore, server (M, High: an operator route that reads across stores).** Kind: agent code.
- BE: `POST /api/platform/companies/{companyId}/records-check`, operator only, fresh sign-in, audited, read-only. For one company it compares: committed submissions against the field drafts' `submitted` marks, in both directions; `pending` submissions past their expiry; evidence registry rows against the objects in the bucket (present, size and stored checksum), and objects with no row; signed agreements against their signature objects. It returns counts and ids only, in bounded pages. It repairs nothing: after a restore a person decides.
- DB: no. The read-only operator policy already covers the tables it reads; the step's first test proves each one, and a table that is not covered is split out as its own database slice.
- Docs: the action in the role matrix (`web/src/lib/access/`) and `docs/ACCESS.md`; a row in the isolation matrix.
- Tests: a clean company returns zeros; each planted case is found (a mark with no record, as after Postgres is restored to an earlier time; a record with no mark; a registry row with no object; an object with no row; a checksum that differs); a caller who is not the operator is refused; one audit row per run; the answer and the logs hold no name, address or path.
- Needs: nothing. Can start now.
