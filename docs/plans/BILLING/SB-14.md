# Billing plan, step SB-14

Part of [the billing plan](../BILLING.md), section 5, "Ordered steps".

**SB-14 Usage tables (M, High: a database job).** Slice: database.
- DB: `member_activity` (company, person, the period's start instant, the time of the first open in the period, latest day seen; one row per person, company and period, section 4.5). On `ai_ledger`, an `outcome` column (`succeeded` or `not_billed`, default `not_billed`, so every existing row counts no credit). On `voice_notes`, a nullable `call_id` that references the AI ledger's (company, call id), unique per company. `billing_usage_reports` (company, month, meter, value, the stamp sent, Stripe's answer, time). `billing_month_close` (company, month, active users, minutes, credits, the allowance and prices used, the credit table version, the extras, Stripe's totals as read back, any difference and when it was checked; once a month is frozen its billing figures cannot be changed, and only the read-back totals, the difference and the check time can be written). The owner's cap and who set it, on `company_billing`.
- Tests: the row-security guard and the catalog suite find all three; one person, two opens in a period, one row; an open after a mid-month subscription start makes a second row for the new period; a ledger row inserted without an outcome is `not_billed`; a voice note cannot name another company's call id, nor a call id that another note already names; a frozen month refuses an update to any billing figure and accepts the read-back totals and the difference; company A cannot see company B's activity, reports or closed months.
- Needs: SB-1. B5, B6, B23.
