# Billing plan, step SB-11

Part of [the billing plan](../BILLING.md), section 5, "Ordered steps".

**SB-11 Read-only in the database (M, High: row-level security, a database job).** Slice: database.
- DB: a function `app_company_writable()` that reads the current company's `access`, and restrictive insert, update and delete policies using it on the work tables (jobs and their customers, claims, files, submissions, estimates, agreements, corrections, links, assignments, coordination, price tables, voice notes and AI results). Not on: the billing tables, `audit_events`, the access outbox, team tables, the two link tables (their read counters change on every open), the AI ledger's settle path, and the operator's context. A transaction marker that only the scheduled workers set lets the Submit repair finish or release a submission that was in progress when the company became read-only; a member's request cannot set it.
- Docs: `docs/DATA.md`; a written list of covered and uncovered tables with the reason for each.
- Tests: for a read-only company each covered table refuses an insert, an update and a delete made directly as the runtime role, and still answers a select; uncovered tables accept theirs; the operator's writes are unaffected; a Submit left pending at the moment of the change is finished or released by the repair worker, and its draft is not left fenced after the company pays; a member's request carrying the worker marker is still refused; every `GET` of SB-9's list still answers, document and signing links included; a test lists every table with a company column and fails when one is on neither list; the whole database suite passes for a `full` company.
- Needs: SB-1; after SB-9 is merged (so the app never meets the database refusal first).
