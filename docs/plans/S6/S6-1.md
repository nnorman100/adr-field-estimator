# S6 plan, step S6-1

Part of [the S6 plan](../S6.md), section 5, "Ordered steps".

**S6-1 Offline test harness and the Safari/Firestore spike (M).** UI, FE, BE, DB, FS: none. Tests and test helpers only, plus a short results note under Corrections; the one product change is the two browser settings (field database id, emulator URL) in `BrowserSignInConfig`, so a test page can run the Firestore SDK. Adds to Playwright (`web/playwright.config.ts`): the Firestore emulator beside the Auth emulator (Java 21, as `test:emu`), a switchable network proxy in front of the app and both emulators so a test can cut and restore the network for the page, the worker and Firestore alike, a helper that seeds a company, access record and `editing` draft with the Admin SDK, and a helper that reads the draft back from the emulator. Then it settles, in Chromium and WebKit with the pinned `firebase` 13.1.0, the questions section 4 rests on: (a) a write made offline survives a reload and is sent once on reconnect; (b) a write the rules refuse after a restart: what the SDK does and what the listener sees; (c) a person signs out and the same person signs in again: are the unsent writes still queued and sent; a different person signing in on the same app instance: are the first person's queued writes withheld, and are cached documents shared; two companies' app instances on one phone: separate caches and queues; (d) single-tab and multi-tab managers with two windows; (e) the start-up hang case (desktop UA, many reloads), whether a watchdog can detect it, and whether the SDK can be started again with the memory cache on the same Firebase app after a persistent start has stalled (if not, the fallback uses a separate app instance, or is dropped); (f) `disableNetwork` before first listen, then `enableNetwork`: queued writes wait. Its tests stay as regression tests. If (b) or (c) differ from section 4, S6-3 and S6-4 change before they start. Needs: S3-13a, S5a-1, S3-12 (all merged). **Can start now** (it carries the browser settings so it does not wait for S6-3).
