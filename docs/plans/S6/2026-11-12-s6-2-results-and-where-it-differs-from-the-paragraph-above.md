# S6 plan correction: 2026-11-12: S6-2 results and where it differs from the paragraph above

Part of [the S6 plan](../S6.md), section 12, "Corrections".

Built as written (shell, manifest, worker, headers, banners, install sheet, tests in both engines), with these choices the paragraph left open. Each is pinned by a test, and the worker and its list are checked by `web/tests/e2e/offline/shell-worker.spec.ts` and `old-worker.spec.ts`.

- **Who writes `ds-me`.** The paragraph has the shell boot from `ds-me`, and S6-3 write it at each online sign-in. With nothing writing it the shell cannot start, so S6-2 holds the store (`web/src/lib/field/ds-me.ts`) and the sign-in page writes one row per (tenant, person) when `/api/me` says signed in: the browser settings, tenant, person id, company name and sign-in address, no email and no token. Signing out removes that row first, and the person stays signed in if the row cannot be proven gone (the sign-in and Team screens both do this). S6-3 adds the role and capabilities to the same row and its own clearing rules (D7, O5); the sign-out removal here is the S6-2 default until then.
- **The worker is built after Next.** `web/sw/sw.js` is the hand-written source (O6, no dependency). `web/scripts/build-sw.ts` (the second half of `npm run build`) fills in the build id and the file list and writes `web/public/sw.js` (git-ignored), served at `/sw.js` with `no-cache, no-store, must-revalidate`. The list is the `/field` page, every `/_next/static` file named by its HTML and its client-reference manifest, the files its head links to and the manifest's icons: 16 files today, no fonts (the shell uses the system font). The build fails when that list names a file that does not exist or misses one the page itself names. Install asks for each file as `<path>?ds-precache=<build id>` (past the HTTP cache), a query no worker answers from its cache, so what is kept is the server's file and never the old app's worker's copy (the old worker's `/manifest.webmanifest` says `start_url` `/app`); it stores a clean copy (status, headers, body; never a redirect or an error) under the plain path, and install fails unless the manifest's `start_url` is `/field`. The worker lets that query through at fetch time. `build-image.sh` now also copies `web/public` into the image, which Next's standalone output leaves out.
- **No `skipWaiting`, no `clients.claim`** in the worker. A first install controls a window from its next load, which is all the offline open needs; a new build waits for S6-6.
- **`/field/*`** is the shell only through the worker (a navigation to it gets the kept page). The server has one `/field` page; a first visit to a deeper path with no worker yet is a 404, and S5a-6 chooses its views from the client state, so it needs no deeper address.
- **The "No signal" banner asks the server.** `navigator.onLine` stays true on an iPhone with Wi-Fi and no way out, and says nothing when the network is cut behind the browser, so the shell also fetches the static file `/reachable.txt` (`web/public`, `cache: no-store`) on open, when visible, on `online`/`offline` and every 15 seconds (5 while down). Any answer means reachable; only a failed request or the 8-second limit means no signal. It is not in the worker's list, so the worker passes it through, and it touches no database (`GET /api/health` is left as it is).
- **"Not saved on this phone"** shows today when IndexedDB cannot be opened, and then takes the place of the "No signal" banner, whose "your work is saved on this phone" would be false. S6-3 raises the same banner (`NotSavedBanner`) when the Firestore cache falls back to memory.
- **Manifest `id` is `/`**, as the old app's, so a phone with the old app installed updates that install if S8 serves the new app at the same address. Icons are the old app's, copied to `web/public`.
- **Test lane:** `lane.ts` gained `serve`, `unserve` and `drop`, so a test can change what a "deployment" serves; the old worker test serves the real `public/sw.js` and the old app's static files through it.
- **Not done here (named in the paragraph's neighbours):** the install sheet gives the iPhone steps only; an Android install button (`beforeinstallprompt`) and the 3-day browser-tab warning belong to S6-5.
- **Not done here, from decision G8 above (D-025):** the first-run sheet does not yet tell an iPhone user in a Safari tab that offline work needs the installed app, and nothing yet limits a Safari tab to online-only; this pull request was built to O1 as it stood. It is a one-line change to the sheet's help text plus S6-3/S6-5's tab notice, for the owner or the next S6 step to schedule.
