# S6 plan, step S6-2

Part of [the S6 plan](../S6.md), section 5, "Ordered steps".

**S6-2 App shell, manifest and service worker (M).** UI: an offline banner ("No signal: your work is saved on this phone"), an "Install to your Home Screen" sheet with the Share-menu steps and its help line, a "Not saved on this phone" banner when persistence is unavailable. FE: one prerendered, data-free page `/field` that boots in the browser from `ds-me` (the browser settings and tenant saved at the last online sign-in; today the sign-in page reads them per request on the server, so a first-ever visit must be online) and reads its data from the Firebase cache; all views are client state under it. A worker at `/sw.js` (scope `/`, the old worker's URL; O6 picks the build) that precaches a manifest of build files generated at build time (hashed `_next/static` files the shell needs, the shell page, icons, fonts, manifest), serves precached assets **and the `/field` shell** from its precache (cache-first; a navigation to `/field` or `/field/*` gets the precached shell, whether or not there is signal), and passes everything else through untouched. A new build reaches a window only through the waiting worker (S6-6). Cache name `ds-field-<build id>`; it deletes only its own old caches (never `dryscope-*` or `alert-disaster-*`, which belong to the old worker). Next `app/manifest.ts` (`id`, `start_url "/field"`, `display "standalone"`, icons) and `next.config.ts` headers (`/sw.js` `no-cache, no-store, must-revalidate`; `/field` revalidating). BE: none. DB, FS: none. Tests (Chromium and WebKit, the proxy cut): the shell opens and reloads with no signal; after a full session the worker's caches hold only the listed shell files; `/api/*` and photo bytes are never cached; an old worker at `/sw.js` (a copy of `public/sw.js`) is replaced once every window of the old app is closed, and the old IndexedDB is untouched (the S8 coexistence check); a deployment between two loads does not change a running window; a build whose precache list misses a file the shell loads fails. Needs: S3-13a (and S6-1's proxy for its offline tests; it can begin with `setOffline` on Chromium while S6-1 lands). **Can start now**; S5a-6 builds its screens inside this shell (section 10).
