# S6 plan, step S6-5

Part of [the S6 plan](../S6.md), section 5, "Ordered steps".

**S6-5 Photo queue (L).** UI: Photos shows each photo's state (waiting, sending, sent, can't send with the reason), a count badge on every field screen, a "Send originals now (use Wi-Fi)" button when originals wait, "Send these photos now, then install the app" when unsent photos sit in a browser tab (an installed app has separate storage and starts empty; install first, on a new job), a 3-day "These photos have been on this phone for 3 days" warning, and "Your phone is nearly full" below a set free-space estimate. FE: `ds-queue` (entries and ArrayBuffer bytes, as in section 4 steps 3 and 4), the queue module `web/src/lib/field/photo-queue.ts` (owner of capture, resize and upload; S5a-6's Photos screen calls it, and if S5a-6 lands first with an online-only upload, S6-5 replaces that call), capture and the 2,560 px resize (canvas; iOS limits canvas area, so the longest side is capped and tested), SHA-256, the drain loop with the foreground triggers and Web Locks, concurrency 2, back-off with jitter, failure classes (retry: network, 5xx, 429 after Retry-After; stop with a reason: 400, 403, 404, 409, 410, 413, 426), pruning of bytes only after a receipt whose hash equals the local hash, `QuotaExceededError` handling (stop capture, nothing half-saved), `navigator.storage.estimate()`. BE: none; a lost response is settled by sending the photo again (S5a-5's route is idempotent). DB: none. FS: none. Tests: **exactly once, photo**: the upload response is lost after the server committed (`route.fetch()` then `route.abort()`), the page is closed mid-upload and reopened, and the network is cut and restored; each ends with one object, one registry row, one reference document and no bytes left on the phone; the same photo id with other bytes is refused and stops; two windows never upload the same entry twice; a fence landing between the receipt and the reference's acknowledgement leaves the bytes on the phone; waiting originals do not stop Finish; company B's drainer never sends A's entries; a full store stops capture without losing earlier photos. The queue works against a fake receipt route until S5a-5 lands; the integration tests join when it does. Needs: S5a-1, S6-3; S5a-5 for the real route. **Client side can start now**, with placeholder screens as in S6-4.
