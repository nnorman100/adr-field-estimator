# Access matrix: Signing links and document links

Part of [Access matrix](../ACCESS.md).

## Signing links and document links (rebuilt app, S5a-11b)

`web/src/lib/links/`, migration `0014_signing_links`. No new capability key: making a signing link is `sign` (owner, estimator); document links are made at signing, and revoking or making one again is `delivery_resend` (owner, office), or `sign` when it replaces no working link. The technician's routes are `requireFlag('price_books', ...)` through the job-access function above; the homeowner's and adjuster's routes are `linkRoute` (`web/src/lib/auth/route.ts`): no sign-in is read, the token travels only in the `X-Link-Token` header (the page address carries it in its fragment, `/sign#token` or `/documents#token`, which a browser never sends), the handler gets only its SHA-256, and a missing, malformed or unknown token answers the same 404 `link_unavailable`. The database keeps only the SHA-256; the token is in no table, log or audit row. A link token is never accepted as a sign-in, and a sign-in is never accepted on a link route. Every answer is `no-store` with no referrer. Delivery is copy, the phone's share sheet or a QR code drawn in the browser; DryScope sends no email or text message (J7).

Limits: 120 requests a minute per client address across the link routes, held per server instance as a keyed hash of the address (never stored or logged), checked before the token is looked up (429 `too_many_requests`); 60 requests a minute per link, counted in the link's row; 10 signing attempts per link, each a signature and a sign request (429 `too_many_attempts`). The token's company is found by `signing_link_company` or `document_link_company` (0014, on the 0004 pattern); everything else runs inside that company's transaction under the company policies. Signed records stay immutable: a link only ever adds an agreement or changes its own row.
