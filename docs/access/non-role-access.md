# Access matrix: Non-role access

Part of [Access matrix](../ACCESS.md).

## Non-role access

- **Anonymous**: `GET /health` and `GET /api/health` (status, schema version, release version, source commit). `GET /api/health/details` needs a signed-in member. In the rebuilt app (`web/`), also `GET /api/sign-in/{address}`: a company's name and sign-in tenant for its sign-in page, both public; an unknown, inactive, tenant-less or malformed address answers 404.
- **Anonymous, rebuilt app: `POST /api/client-errors`** (TC-2): a browser or phone sends error reports before or after anyone signs in, because the sign-in pages fail before a person exists. It is public and write-only, and has no role-matrix key because it reads no company data (no Postgres, no Firestore, no identity). Limits: the body must be JSON of at most 8 KB and at most 20 reports, each field bounded by a Zod schema (otherwise 400, 413 or 415); each caller (its connecting address, held only as a hash in memory) may have at most 20 reports a minute written and each Cloud Run instance writes at most 60 in all; the excess is answered 202 and counted. The instance cap logs nothing; a caller hitting its own cap writes one fixed warning line a minute with no address in it (S3 security review, F6). It writes each report to the server log as an Error Reporting event for the service `dryscope-web-client`, built only from the error name, a message scrubbed again on the server by the same allowlist as the browser (percent-decoded, then every digit run becomes `#`, anything with an `@` becomes `[email]`, any run of 20 or more token characters or a bearer value becomes `[token]`, and URL query strings are dropped) and cut to 300 characters, stack frames of the app's own scripts (function name scrubbed the same way, line and column, with the fixed name `app.js` in place of the script path; frames from other scripts are dropped and no path is logged), the route pattern (never the address), and the browser family; no body, header, address, person or company is logged. Native CSP reports (`application/csp-report` and `application/reports+json`) use this same endpoint and share every batch, caller and instance cap with error reports; the body cap is the same 8 KB except for a Reporting API batch (`application/reports+json`), which may be up to 64 KB because Chrome repeats the whole policy in each of up to 20 batched reports. They pass bounded Zod schemas and log only a fixed directive, blocked-resource category, page route pattern and browser family; no original policy, URL, query, referrer, source file or script sample is logged ([CSP observation](../security-csp.md)). App Check (TC-5, monitor mode) records the token's outcome for this route like any browser-facing route and never refuses ([App Check, monitor mode](../architecture/browser-security.md#app-check-monitor-mode-tc-5)).
- **Homeowner signing link** (`/api/sign*`): single-use token, expires in 7 days, stops working on any edit; acts as the technician who sent it and needs that technician to still hold `sign`. After signing, the used link can still view the documents for 30 days. Limits: 120 requests a minute per client address across link routes and 10 signing attempts per link. In the rebuilt app (S5a-11b) see "Signing links and document links" below; there the address limit is held per server instance, so the real ceiling is 120 times the instances running.
- **Document link** (`/documents`): read-only, bound to one signed agreement and one document set, expires in 30 days, revocable, multi-view; the technician who created it must still hold `sign`. In the rebuilt app (S5a-11b) both sets' links are made at signing, the owner or office revokes one (`delivery_resend`), and a link works while its maker holds `sign` or `delivery_resend`.
- **Server-only**: Cloud Run runtime service account `adr-runtime@…`; background jobs (vault backup, monitoring).
