# Job access, roles, archive, signing and Postgres

- **A role's capability and owning the field work are two checks.** Use `jobAccess` in `web/src/lib/jobs/access.ts` with its options as documented there. `fieldWork` means the caller owns the job's field work, whatever their role: a company owner is not exempt. `customer` lets an estimator save customer details only while they own the field work; being assigned is not enough. In the other direction, do not hide an owner's Archive or Copy because field ownership moved.
- **Repeat authorization under the lock.** Ownership, the link token and "not yet signed" checked before the job lock can be stale by the time you hold it.
- **Archived means HTTP 410, on every job route except archive and restore.** Recognise it by the status, not by a code in the body, which a phone can lose. Only request archive screens and lists for roles that hold the archive capability; anyone else gets a certain 403. An archive can commit in Postgres while the Firestore draft is still editable, so the screen must go read-only on the 410 alone.
- **Know which revision you advance.** Office notes and the field owner have their own coordination revision. Only a change to what the documents say advances the job revision, which voids a reviewed estimate and its signing links. Customer and claim edits do change the documents.
- **Signing is replayable.** A repeated signing request returns the existing receipt and must not renew or rotate document tokens. Rotating a link needs the revoke capability. Bind everything on a signing page to the token in the address, so changing the token cannot sign one estimate while showing another.
- **What leaves through a link is a closed list of fields.** Removing the keys you thought of has leaked owner-only pricing through four review rounds. The same goes for trace attributes and log fields: name each one, no wildcards. After an access refusal, cached customer details leave the screen.
- **Postgres.** The read-only mode must be set before any query in the transaction, and setting the company is a query: pass `readOnly` to the tenant helper in `web/src/db/tenant.ts`. A policy keyed on a session flag can open every company to the table owner. A step the plan marks "DB: no" gets no migration; ask instead.
